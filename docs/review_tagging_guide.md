# 评论标签方案 v1

目标：用少量、边界清楚的标签，回答用户为什么买、在意什么、用得怎样，以及优先改进什么。适用于本项目袜子及内衣评论。

## 1. 数据依据与设计原则

- 实际文件是 `data/sample.csv`（不是 sameple.csv），共 62 条，已逐条阅读标题与正文；其中 60 条为袜子评论、2 条为内衣评论。星级分布：1 星 9 条、2 星 7 条、3 星 7 条、4 星 9 条、5 星 30 条。
- 本方案依据原始 `title`、`content`，不继承现有 `tags`、`theme_ids` 的判断。`product_name` 只帮助识别品类，不能充当用户诉求或使用经历。
- 只设两层：**分析维度 → 标签**。场景、属性、旅程是可组合的维度，不再层层嵌套；具体问题用短文本记录。
- 一条评论可有多个观点，每个观点单独关联原话、属性和情绪。未提及就留空，不能把所有栏目强行填满。
- 评论以购买后反馈为主；购买前动机、购买中障碍，仅在用户明确回顾时标记。内容兴趣、实际退换、明确竞品选择理由在样本中证据有限，保留入口，不补造结论。
- 以下是标签定义和人工示例，不是全量自动标注结果，也不是已验证的机会排名。

## 2. 标签总览

| 分析维度 | 二级标签 / 可选值 | 使用规则 |
| --- | --- | --- |
| 用户旅程 | 购买前、购买中、购买后 | 按观点发生的阶段判断，一条评论可跨阶段 |
| 使用场景 | 日常穿着、工作通勤、运动步行、居家睡眠、送礼 | 可多选；未写具体场景则留空 |
| 产品属性 | 尺码与贴合、舒适度、面料、耐穿性、设计与功能 | 核心属性固定 5 类 |
| 其他评价对象 | 价格与价值、交付与服务、整体评价 | 不挤入核心属性；笼统“质量好/差”归整体评价 |
| 满意度 | 正面、负面、中性、褒贬并存 | 与具体评价对象绑定；没评价就留空 |
| 后续行为 | 退换、复购、不再购买 | 另记“意向 / 已发生”，不得凭差评推断 |

动机、关注点、障碍、内容兴趣、竞品原因、未满足需求与问题原因，均用有原话支持的短句记录，不另建大型标签库。品类、尺码、品牌名、鞋型、天气、使用时间也作为上下文，不新增层级。

## 3. 用户旅程洞察

### 3.1 购买前：使用场景、需求动机与内容兴趣

| 字段 | 含义与边界 | 示例 / 规则 |
| --- | --- | --- |
| 使用场景 | 在哪里、做什么时使用 | 码头上班→工作通勤；每天走 5–10 英里→运动步行；圣诞礼物→送礼 |
| 需求动机 | 用户要解决的问题或想达到的效果 | 想要不露袜的休闲外观，同时减少脚汗、异味与摩擦 |
| 内容兴趣 | 用户明确希望看到的信息、教程或对比 | 仅明确索要尺码指南等内容才记录；“偏小”本身不等于用户想看尺码教程 |

场景边界：普通穿着归日常穿着；明确在家或睡觉归居家睡眠；普通走动不自动算运动。寒冷、球鞋、窄脚等记为场景条件或用户特征。产品介绍式的“适合运动”需标明为泛述，不能当作实际运动经历。

场景不必属于购买前：实际穿着场景可以关联购买后观点。为家人购买不自动等于送礼，要有 gift、Christmas 等明确依据。

### 3.2 购买中：购买关注点、决策障碍与竞品选择原因

| 字段 | 含义与边界 | 样本依据 |
| --- | --- | --- |
| 购买关注点 | 下单时明确在意的条件，复用产品属性或价格标签 | “I bought these socks, hoping that they would fit my size 11.5 feet.”→尺码与贴合 |
| 决策障碍 | 用户明确说某因素曾让其犹豫或不买 | 内衣评论提到担心下围上移，曾因此不选无钢圈内衣 |
| 竞品选择原因 | 明确比较对象及偏好、选择或放弃的原因 | R12FK3M25KB32E 希望像 “True bras” 一样更有弹性；这是比较偏好，不能说用户已转购 |

“太紧”是购买后问题，不自动升级为购买障碍。“order another brand”只有泛指替代建议，不能编出竞品名称。品牌、比较点、选择状态分别记录，未说已购买竞品则状态留空。

### 3.3 购买后：满意度、真实体验与行为驱动

- **整体满意度**：仅根据整体评价语判断；星级作为独立元数据保留。只有属性评价时，可不填整体满意度。
- **真实使用体验**：记录实际穿着、洗涤、使用时长与结果。未使用的礼物评价标记为“预期”；泛泛复述商品功能标记为“泛述”，不能计入实际体验统计。
- **退换 / 复购驱动**：行为、状态与原因须有明确联系。R10I96XZNOPP00 明确因为不耐穿而不再购买；R10NM49I4BTBTU 同时提到多次购买与未来继续购买，但未明确原因，原因留空。
- **未满足需求**：区分“用户明确希望”和“分析推导”。前者保留原话；后者只能写成待验证机会，不作为用户明确需求计数。

## 4. 产品属性分析

### 4.1 核心属性：只保留 5 类

| 属性 | 包含 | 不包含 / 易混边界 |
| --- | --- | --- |
| 尺码与贴合 | 偏大偏小、松紧、脚型适配、袜口束紧、内衣下围贴合 | 穿着中掉跟、滑落归设计与功能；已明确疼痛可另记舒适度 |
| 舒适度 | 柔软触感、磨脚、压迫、疼痛、整体穿着舒服与否 | “太紧”但未说不适，只标尺码与贴合；材料成分归面料 |
| 面料 | 厚薄、材质、弹性、透气排汗、保暖、异味表现 | 厚不等于好、薄不等于差，按语境判断；破洞归耐穿性 |
| 耐穿性 | 破洞、磨损、洗后变形缩水、使用后性能衰退 | “质量差”却没有具体表现，归整体评价，不猜测破洞 |
| 设计与功能 | 不露袜、袜筒高度、防掉跟、地面防滑、缓冲保护、支撑塑形、颜色外观 | 明确“薄”归面料，明确“缺缓冲”归本类；两者都说才同时标记 |

同一属性的细节保存在 `detail`，例如“袜口太紧”“首次穿着破损”“颜色选择少”，这些是摘要，不是第三层固定标签。

### 4.2 场景与属性满意度必须关联

以观点为单位记录“场景 + 条件 + 属性 + 满意度”，不能把整条评论中每个场景与每个属性任意配对。

| 评论原话 / ID | 场景与条件 | 属性与满意度 |
| --- | --- | --- |
| “Work a dock and toes are freezing off possibly literally.” / R11CAJV84KU5ME | 工作通勤；寒冷码头 | 面料·保暖：负面；同评另有柔软舒适的正面观点，不能被覆盖 |
| “I normally walk 5-10 miles a day and these have held up well so far.” / R115TJQ183XEHZ | 运动步行；每天 5–10 英里 | 耐穿性：正面，限于目前体验 |
| “She did say it was too stiff to sleep in” / R12FK3M25KB32E | 居家睡眠；女儿 | 舒适度：负面；不能与女儿日常穿着满意混为一个结果 |

满意度规则：无褒贬的材质或厚度描述为中性；同一对象同一上下文确有好坏并存且无法拆开时才用褒贬并存。不同属性、场景、使用者或时点，优先拆成独立观点。

例如 R11T7ASNIMOLS0 虽为 5 星，但 “Not the socks for me too thin” 应标面料负面。“Would be comfy if…” 是条件式期待，不能标已实现的舒适正面体验。

## 5. 低满意度属性与机会点下钻

### 5.1 质量因子、问题表现与原因

负面观点仅增加三个字段：`detail`（出了什么问题）、`cause`（用户明确归因，没有则空）、`impact`（造成什么影响）。原因另注明“用户归因”，不能当作已验证的工程根因。

| 待关注质量因子 | 代表性原话与 review_id | 结论边界 |
| --- | --- | --- |
| 尺码准确、贴合不挤脚 | “These socks are so tight I can't keep them on my feet because they scrunch my toes.” / R12QEMPQJHNVGF | 明确挤脚、无法持续穿着；不能仅凭此判定生产尺寸不合格 |
| 日常使用寿命 | “One sock is broken at the fist use.” / R12T4D1V7L3H1E | 首次使用破损，原文拼写保留；未说明破损位置或制造原因 |
| 厚薄与缓冲匹配需求 | “Not cushioned, mush too thin.”（标题）/ R11159CBXQ9CUM | 面料与缓冲都负面；不能推断“所有用户都希望加厚” |
| 保暖符合场景 | “Absolutely not good for cold weather.” / R11CAJV84KU5ME | 明确寒冷场景不适用；不是所有场景均不适用 |
| 穿着时保持位置 | “they didn’t stay on my heel” / R10B0WAE663W37 | 防掉跟失效；不推断一定由尺码或硅胶造成 |

R10TWSV86TX6UU 既报告短期破洞，也说 “I think they made the socks just a little too thin.”：破洞是报告的问题，太薄导致破洞是用户猜测，两者要分开。

只有泛泛 “Poor quality” 的评论，保留整体负面，不进入某一质量因子的根因统计。

### 5.2 未满足需求与机会优先级矩阵

明确需求示例：

- R10TWSV86TX6UU：“If they can fix the socks to be slightly more durable, they would be perfect.”→提高耐穿性。
- R1152MP5GQBG97：“I wish they came in some prettier colors!”→增加好看的颜色。
- R12FK3M25KB32E：“I was hoping for something with more stretch like the True bras.”→增加弹性；其他使用者认可支撑，不能简单建议所有款都变软。

优先级采用 **出现频率 × 影响程度**，不额外增加用户标签：

|  | 高影响 | 一般影响 |
| --- | --- | --- |
| 高频 | P1：优先验证并改进 | P2：安排优化或明确产品定位 |
| 低频 | P2：专项核查 | P3：观察、收集更多反馈 |

- 频率：同品类内，同一问题涉及的去重 `review_id` 数 ÷ 该品类全部有效评论数；试行以 ≥10% 为高频。必须同时展示分子、分母；样本不足 30 条时标“样本不足”，不机械定级。阈值是工作规则，不是统计显著性标准。
- 影响：明确无法使用、疼痛、首次/短期破损、因该问题退换或不再购买，记高影响；可继续使用的偏好不符记一般影响；后果未明则待核实。星级不替代影响判断。
- 一个问题含不同影响时，按两种影响分组统计，避免一条严重评论把所有相关反馈都归为高影响。明确健康伤害描述需单独人工核查，不等待高频。
- 每项机会输出：问题、相关属性与场景、明确需求/分析假设、评论数与占比、影响证据、优先级、建议验证动作。不要把建议写成已证实根因。

样本支持的待验证方向：尺码适配及说明、短期破损、薄款与缓冲需求匹配、寒冷场景适用说明。颜色扩展仅见少量内衣证据。上述方向尚未逐条编码计数，因此不直接赋予 P1/P2/P3。

## 6. 用于 LangExtract 的最小抽取约定

参考 [LangExtract 官方 README](https://github.com/google/langextract#quick-start)：用明确指令与示例定义抽取，原话放入 `extraction_text`，分类放入 `attributes`，并核验结果能定位到输入原文。这里提供设计约定，不包含安装或模型调用。

每条评论以 `title + 换行 + content` 为输入，`review_id` 在外部保留。采用单一 `extraction_class="review_insight"`；每条结果对应一个观点。

| 字段 | 必填情况 | 含义 |
| --- | --- | --- |
| extraction_text | 必填 | 原文中的连续片段，保留语言与拼写，不翻译、不拼接 |
| journey | 明确时填 | 购买前 / 购买中 / 购买后 |
| topic | 评价对象明确时填 | 上述 5 个核心属性或 3 个其他对象 |
| sentiment | 有评价时填 | 正面 / 负面 / 中性 / 褒贬并存 |
| detail | 必填 | 简短中文摘要，不扩充原意 |
| scene、context、subject | 有证据时填 | 场景、鞋码/天气/时长等条件、实际使用者 |
| evidence_type | 必填 | 实际体验 / 预期 / 泛述；明确回顾的决策或行为也归实际体验 |
| motivation、content_interest、purchase_focus、barrier | 有证据时填 | 动机、内容兴趣、购买关注点、障碍短句 |
| competitor、comparison_reason、choice_status | 有证据时填 | 竞品名称或泛称、比较原因、明确选择状态 |
| behavior、behavior_status、behavior_reason | 有证据时填 | 退换/复购/不再购买，意向/已发生，明确驱动 |
| cause、impact、unmet_need | 有证据时填 | 用户归因、影响、用户明确提出的未满足需求 |

分析师推导的机会与汇总优先级另表生成，不放进原文抽取结果。字段缺失表示未提及；不用“其他”填充。一个片段涉及两种属性时，允许分别输出并共享证据，汇总按评论去重。

示例（来自 R10I96XZNOPP00 正文，review_id 作为外部关联键）：

```json
{
  "extraction_class": "review_insight",
  "extraction_text": "Would not buy again due to durability",
  "attributes": {
    "journey": "购买后",
    "topic": "耐穿性",
    "sentiment": "负面",
    "detail": "因耐穿性问题不再购买",
    "evidence_type": "实际体验",
    "behavior": "不再购买",
    "behavior_status": "意向",
    "behavior_reason": "耐穿性差"
  }
}
```

## 7. 标注与统计检查

1. 原话必须能在对应评论标题或正文中原样找到；无法定位的抽取先排除并复核。
2. 属性负面率 = 该属性有负面或褒贬并存评价的去重评论数 ÷ 明确评价该属性的去重评论数；与第 5 节“问题占全部评论比例”分开显示。中性算明确评价，无评价不算。
3. 场景分析仅汇总有明确关联的观点；实际体验与预期/泛述分开；品类分别统计，不能将袜子与内衣混排。
4. 先人工复核偏紧与不适、薄与缓冲、贴合与掉跟、五星负面、条件式期待、多使用者这六类边界，再推广到完整数据。
5. 本次仅新增文档，原 CSV、列名与现有分析字段均未修改。
